ChatFei / Message Pipeline

一条消息，如何到达对方手机？

发送方通过 HTTP 把消息交给服务器；服务器先持久化，再通过已有的 WebSocket 长连接通知在线接收方。接收方收到事件后，重新拉取最新消息。

Android 客户端

发送方手机

  1. AES 加密正文
    生成唯一 clientMessageId。
  2. 调用发送接口
    POST /api/conversations/{id}/messages。
  3. 等待服务器响应
    成功后刷新当前会话。
HTTPS
Spring Boot + PostgreSQL

ChatFei 服务器

  1. 认证与权限校验
    确认发送人属于该会话。
  2. 消息写入数据库
    离线时也不会丢失。
  3. 查询会话成员
    取得全部接收用户 ID。
  4. 查找在线连接
    按用户 ID 取 WebSocketSession。
  5. 推送 MESSAGE_CREATED
    只向当前在线成员实时发送。
WEBSOCKET
Android 客户端

接收方手机

  1. 收到 WebSocket 事件
    RealtimeClient.onMessage 被调用。
  2. 触发 refresh()
    刷新会话及在线用户。
  3. 拉取最新消息
    GET /messages 并更新聊天界面。

在线结果：服务器通过现有 WebSocket 连接立即通知对方；对方收到事件后从服务器拉取最新消息。

离线结果：消息已经保存在数据库，但服务器找不到对方的 WebSocket 连接，因此不会立即到达手机；对方下次启动 App 后再从服务器拉取。目前没有接入 FCM 离线推送。

三个关键代码点

发送、转发、接收

① 手机发送ApiClient.kt
fun sendText(token, conversationId, text) =
  postJson(
    "/api/conversations/$conversationId/messages",
    token,
    JSONObject()
      .put("type", "TEXT")
      .put("encryptedText", encrypt(text))
  )
② 服务器保存并推送ConversationController.java
MessageView message = chat.send(
  me, id, clientMessageId, type,

);

realtime.send(
  chat.memberIds(id),
  "MESSAGE_CREATED", message

③ 对方收到事件RealtimeClient.kt
override fun onMessage(
  webSocket: WebSocket,
  text: String
) {
  listeners.toList().forEach {
    it(text) // ViewModel 调用 refresh()
  }
}
不是手机之间直连

发送方和接收方不会互相建立连接，所有消息都经过 ChatFei 服务器。

实时事件不是最终数据源

WebSocket 负责通知“有新消息”，数据库和 GET /messages 才是最终数据来源。

当前没有离线系统推送

前台服务维持在线连接，但 App 真正离线时不会像微信一样收到系统通知。
